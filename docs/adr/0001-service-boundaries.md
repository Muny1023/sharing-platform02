# 按业务边界拆分 Java 服务

状态：accepted

后端拆分为网关、账号、内容和通知四个服务，`cloud-common` 只承载跨服务契约。账号拥有账号数据，内容拥有帖子及互动数据，通知拥有通知数据；网关不拥有业务数据。这样可以在保持原有 HTTP 接口的同时形成清晰的数据所有权，避免把强关联的帖子、评论和互动过早拆成相互调用的小服务。

## 考虑过的方案

- 按单个功能拆分帖子、评论、点赞和收藏：边界过细，会放大远程调用和事务协调成本。
- 保留单体后端：迁移目标无法获得服务级部署和故障隔离能力。

## 后果

内容服务承担较宽的业务范围，但内容内部事务仍可保持本地；跨边界访问必须通过明确的内部接口完成。
