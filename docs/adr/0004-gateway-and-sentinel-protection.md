# 在网关集中执行入口治理

状态：accepted

所有前端请求继续访问网关，由网关负责路由、CORS 和 Sentinel 路由治理。JWT 目前由 account、content、notification 三个业务服务分别校验，网关不承担统一 JWT 过滤。Sentinel 规则通过 Nacos 动态配置：认证接口保留每 IP 三秒最多十次的入口限流，其他 `/api/**` 路由初始按每实例每秒一百次保护，并在错误比例达到百分之五十且满足最小请求数后熔断。降级响应保持 `RestBean` 结构，状态码使用 429 或 503。

## 考虑过的方案

- 只在各业务服务限流：无法在请求进入系统前统一保护，也会重复实现入口策略。
- 在网关增加统一 JWT 过滤器：可以集中处理认证，但当前各业务服务仍需独立校验，先保持现有职责边界。

## 后果

业务服务继续校验 JWT，网关不能作为唯一信任边界；原有 `FlowLimitFilter` 继续保留，用于认证接口的 IP 级保护。后续若增加网关统一鉴权，需要单独更新本 ADR 和对应测试。
