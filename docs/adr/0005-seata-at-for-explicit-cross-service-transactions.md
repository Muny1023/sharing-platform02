# 用 Seata AT 验证显式跨服务事务

状态：accepted

需要跨账号和内容服务验证的事务使用 Seata AT，但只通过专用 `seata_demo_*` 表演示成功提交和人为异常回滚，不直接污染真实账号、帖子或通知数据。Seata Server 先使用 file 存储运行，参与事务的业务数据库在共享 `test` 库中准备一张 `undo_log` 表；Seata Server 本身不建立业务库全局事务表。

## 考虑过的方案

- 直接把真实业务写操作作为演示事务：验证风险不可接受，回滚失败会污染用户数据。
- 使用 Seata TCC：控制力更强，但需要为迁移阶段的每个动作编写 try-confirm-cancel 逻辑。

## 后果

Seata 只覆盖明确需要跨服务原子性的场景；内容本地事务和通知异步流程不因此改造成全局事务。
