# 通知和邮件采用最终一致性

状态：accepted

帖子、评论和互动先在内容服务本地事务中完成，再通过 RabbitMQ 发布通知事件，由通知服务异步消费站内通知和邮件任务。事件必须包含唯一事件标识、业务 ID 和展示快照；消费者按事件标识幂等，快照优先用于展示，OpenFeign 只承担缺失数据的补偿查询。

## 考虑过的方案

- 在内容请求中同步完成通知和邮件：会把邮件系统的延迟和故障传递给核心内容写操作。
- 只发送业务 ID、不保存快照：历史通知会依赖远程补查，源数据变化后展示语义也会漂移。

## 后果

用户可能在内容写入成功后短暂看不到通知；系统必须提供消费重试、重复投递幂等和补偿查询能力。
