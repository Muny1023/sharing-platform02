# 第一阶段共享本地数据库

状态：accepted

第一阶段所有 Java 服务共享现有本地 MySQL 的 `test` 数据库，但代码访问边界按服务划分：账号只拥有账号表，内容只拥有帖子和互动表，通知只拥有通知表。选择共享数据库是为了降低迁移期的运维和数据搬迁风险，同时保留未来拆分独立数据库的清晰所有权。

## 考虑过的方案

- 立即为每个服务建立独立数据库：隔离性更强，但会把迁移、联调和数据同步问题同时引入。
- 所有服务自由访问全部表：迁移最快，但会形成不可逆的隐式耦合。

## 后果

代码评审必须阻止越界表访问；Seata AT 的业务库事务表在共享库中统一准备，真实业务数据仍需通过服务边界访问。
